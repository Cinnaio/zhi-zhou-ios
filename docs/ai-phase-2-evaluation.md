# 第二批 B6 验收与质量评估

B6 先完成可运行的自动检查，再把主观质量评估留给获得独立授权的后续运行。本轮不调用真实付费模型，因此当前状态是“框架完成，质量未验证”。

## 自动验收

自动检查只回答可复现的工程问题：

| 维度 | 通过条件 | 证据来源 |
| --- | --- | --- |
| 输入 | 六组续写 brief、六组封面需求数量固定，字段和 Unicode/范围合法 | `phase2-fixtures.test.ts` |
| 冻结 | 任务参数包含服务端规范化后的 brief、正文版本、选段范围或封面元数据 | B1/B3/B5 API 回归 |
| 来源 | 续写起点、画像、候选封面和历史图片关联到正确小说/任务 | API PGlite 回归 |
| 状态 | 建议与应用、候选与当前封面、历史恢复状态彼此分离 | B3/B5 API 回归 |
| 幂等 | 重放同一操作 ID 返回同一结果；重复应用/版本冲突不会二次写入 | B3/B5 API 回归 |
| 调用预算 | 固定夹具只记录 8 次续写文本、8 次封面文本、6 次封面图像的声明预算；auto 每组 2 次文本，exact 为 0 次 | `phase2FixtureBudget()` 与封面 mock 回归 |
| 付费边界 | 测试使用 fetch 桩或本地字节，不向真实文本/图像供应商发送请求 | 测试输出与环境变量 |

来源泄漏、错书结果、错误覆盖、重复应用或重复计费调用任一项即不通过。桩返回的句子或图片只能验证状态机和数据流，不能作为语言或视觉质量证据。

## 经授权的真实模型评估

后续若单独授权 A/B 评估，必须保持固定夹具、供应商、模型、温度、token 上限、图像尺寸和重试上限；先批准总调用数与预算上限，失败不得无限重试。每次运行保存盲评顺序与原始输出，并记录：

```text
runId / fixtureId / provider / model / request parameters
text calls / image calls / prompt tokens / completion tokens / latency
actual cost (unknown when provider does not return it)
```

写作由不看实现的评审按 1–5 分记录：人物事实、时间线、起点衔接、要求遵循、语言自然度。封面按 1–5 分记录：需求符合、构图、视觉一致、文字可读（仅在要求文字时评分）。原始输出与评分分开保存，避免先看实现细节影响盲评。

在没有上述授权和真实输出前，不给出质量均分、供应商优劣或费用结论，也不改变既定模型、来源、幂等或保留策略。
