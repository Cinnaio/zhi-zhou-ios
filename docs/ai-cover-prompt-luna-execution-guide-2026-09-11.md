## 3. Astra 已定决策：Luna 不再自行选方案

### 3.1 调用流程

继续保留：题材判定一次 + 场景生成一次 + 图像生成一次。独立描述词任务只做前两次；编辑后的完整 prompt 以 exact 生图只做一次图像调用。

不合并文本调用，不增加第三次“纠错/压缩/评审”调用。文本模型没有配置时继续提供本地模板结果；已经配置但请求失败时保留现有任务失败语义，不静默伪装成功。

### 3.2 内部结构与兼容性

建议新增 `api/src/services/ai/cover-prompt.ts`，承担实际被生产路径调用的纯函数：上下文准备、方向解析、分块渲染和预算压缩。不得为测试另造一份不接生产的组装器。

使用内部 typed brief（名称可调整），至少包含：小说上下文片段、选定构图、人物呈现规则、唯一风格/色板/光线、最终场景、文字块、必要限制。它不新增公开 API、不新增数据库表、不要求文本模型返回 JSON。

第二次文本调用仍输出英文场景正文，保留流式能力。通过输入规则收敛故事场景，不改成结构化 JSON 流式协议。纯函数可验证结构冲突；自然语言是否捏造事实仍是后续人工评估边界。

`CoverPromptMetadata` 可新增可选 `promptTemplateVersion: 2`，仅用于新的自动结果追溯；旧结果缺字段即旧版本/未知，不补造。exact 不伪造版本、题材或配置已生效。保持原 request hash、operationId、clientRequestId、variationId 和重试策略，不借本轮引入历史模板执行引擎。

### 3.3 事实与上下文

- 书名/作者来自现有字段；默认 renderTitle 行为沿用路由契约，不统一修改整个产品默认值。
- 两次文本调用使用同一份准备后的简介。先折叠多余空白和移除明显 HTML 标签，再按完整句/段选取，最多 800 UTF-16 单元；超过上限保留开头与结尾的完整片段，在中间明确标记省略。无标点长段才按 Unicode 标量边界裁剪。
- 这个 800 上限只替换原 300 的上下文取样，不改变模型 maxTokens。记录本地夹具输入长度变化，不据此声称费用不变。
- 分类最多沿用三项；不把分类名直接当人物设定。将元数据作为清楚分隔的资料块，系统指令说明资料内的命令不执行。
- 第二次调用只用已给资料确定时代、地点、身份、关系、物件；资料不足时允许灯光、留白、材质等中性演绎，不新增皇帝、婚约、凶案、戒指等剧情事实。
- 最终送图像模型不再重复整段原始简介与题材清单；由场景承载必要事实，防止提示词变成剧情梗概。
- 文字块保留完整书名、作者（规范化前后策略沿用现有 trim）；不得继续 `slice(0,60/40)` 后静默渲染半个名字。无法在总长度内容纳时明确失败，不生成错字版替代。

### 3.4 构图与风格唯一来源

先调用现有 `resolveCoverDirection` 确定方向。显式 composition 必须生效；auto 继续使用原散列选择方式，不承诺不同 variation 一定不同，不声称可复现相同像素。

| 构图 | 场景生成要求 | 言情概念处理 |
| --- | --- | --- |
| portrait | 一个主要人物；只采用资料支持的服饰/身份，背景从简 | 手势/视线/局部动作，不另加双人远景 |
| duo | 两个清晰区分的角色及一个关系动作；未知性别不默认一男一女 | 距离或互动，不能改成无人静物 |
| environment | 场所为主体；人物可缺席或占很小比例 | 地点与关系痕迹，不强制人物特写 |
| symbolic | 一个物件或非具象符号为焦点；人物不强制出现 | 物件/余痕，禁止额外强制双人主角 |
| silhouette | 由剪影、背影或影子表达，不要求精细面容 | 姿态与轮廓；不额外要求面部表情 |
| off_center | 明确一个偏置主视觉与留白方向 | 只补动作或情绪，不独立再选构图 |

言情模块负责关系/情绪线索，不再独立强制八种构图之一。若保留 visualConcept 字段，从最终 composition 确定兼容值并确保 metadata 与最终提示词一致；保留旧导出函数参数兼容，可增加可选 composition 参数。

将 preset 的画风、色板、光线、文字气质拆成可组合字段。选中 preset 后只输出它的一套风格；情绪只细化强弱、距离、明暗，不追加另一套颜色名单。genre 只参与推荐和资料不足时的中性兜底，不再追加默认色彩、光效和固定角色服饰。

`minimal_typographic` 有字时以标题为主要图形、图像为从属，并在所选构图内安排从属图形；无字时改为极简象征图形和留白。`pastel_romance`、`botanical_literary` 等显式风格可有低权重装饰纹理，不因此强塞花园/花束等剧情物件；移除与显式风格冲突的全局禁粉/禁花清单。

### 3.5 最终提示词与长度规则

固定顺序：主体与故事锚点 → 构图 → 唯一画风/色板/光线 → 文字 → 必要限制。用简短完整句，避免列出多个替代地点/角色/动作。

- 沿用公开 `coverPromptMaxChars` 的 UTF-16 长度定义与 100–10000 范围，不在本轮迁移接口计数协议。
- 所有裁剪不得切断代理对；测试 emoji、长中文书名、组合字符。组合字符不要求完整字素算法，但记录这一限制。
- exact 继续沿用 `normalizeCoverPrompt`：trim 后原样发送、超长拒绝；不裁切、不补 no text、不加入模板版本指令。
- 自动生成用 block 优先级压缩：删除平台冗余修饰和低权重装饰 → 用 preset/构图紧凑版本 → 删除场景中低优先背景句。书名/作者完整、主视觉、明确构图、文字开关、比例是必需块。
- 普通预算（例如 2000）给场景预留至少 35% 的可用字符上限；这是预留容量，不为满足比例而填充废话。第二次模型输入给出计算后的场景字符预算，原 60–90 words 改为预算内的紧凑完整句。
- 场景输出超额优先选完整句；若单句过长不能保留必要主体，采用从已准备 brief 构造的短场景，不硬切英文半句话，不追加模型压缩调用。不得声称本地回退完全保留模型创作细节。
- 必需块紧凑版仍超过设置（尤其 100 字符上限＋长书名）时抛现有 invalid 错误，清楚提示上限不足；必须在图像调用前终止。可预检出的必需块不足在文本调用前终止。
- 无字模式正向块中没有标题/作者/字体生成要求；末尾保留 `no text, no watermark, no logo`。有字模式明确“仅准确渲染提供的书名和作者，不添加其他文字”，不同时写 `no text`。
- 默认作者字形简洁可读，去掉每个题材强制装饰框、发光横线、近乎不可见灰字等要求。沿用中心安全区域与 2:3 描述，不更改实际 image size 配置；尺寸比例不符属于已有配置问题，另列记录。
